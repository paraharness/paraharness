## 4. Detailed Implementation Requirements

### 4.0 Single-Kind File Separation, Parameter Co-Location & JSDoc Discipline (`docs/CODING_GUIDELINES.md` §§1–3)
1. **Single-Responsibility Decomposition, Single-Kind Entity Files & Co-Location (`Rules 1.1–1.8 & 3.1–3.4`)**:
   - Every file, class, method, and function in `packages/core/src/runtime/**` and `packages/core/test/fixtures/**` must have **one clear responsibility at one uniform level of abstraction** (`docs/CODING_GUIDELINES.md` §§1–3). Orchestrators (`executeLoop`, `executeAgent`, `executeFlow`, `executeForkBatch`, `executeSpeculateTournament`, etc.) only sequence high-level phase calls and lifecycle boundaries (`try / finally`), delegating context extraction, state initialization, lesson recall/scoring, iteration phases, and outcome projection to focused `internal/` functions. Builders are free and expected to extract additional focused `internal/` phase, predicate, and projection helper files beyond the baseline §3 table whenever responsibilities separate, while preserving all planned public exports.
   - Unrelated or different-kind declarations (`interface`, `function`, `class`, `const`, `type`) must **never** live in the same file in `packages/core/src/runtime/**` or `packages/core/test/fixtures/**`.
   - Dedicated 1:1 `*Params` / `*Options` interfaces (and their reachable sub-interfaces) for a single function or class are co-located in the same file as that function or class (`Rules 1.3, 1.6, 3.3`), while `*State`, `*Entry`, and multi-module shared state/result interfaces (`ScopeLockEntryState`, `PoolRuntimeState`, `ActiveServiceEntry`, `PolicyEvaluationResult`, `AgentTurnSessionState`, `LoopExecutionState`, `FlowExecutionContext`, `LaneQueuedItemState`) live in their own dedicated `interface` files (`Rule 1.2`).
   - Every `class` (`ScopeLockManager`, `StepContinuationQueue`, `PoolManager`, `ServiceSessionRegistry`, `LaneScheduler`, and each `test/fixtures/*` class) gets its own file (`1 class per file`); every `const` lives in `*.constants.ts`; every `type` lives in `*.types.ts`.
2. **JSDoc Anatomy & Tag Completeness (`Rules 2.1–2.4`)**:
   - Every `class` (and its constructor, methods, and properties), `interface` (and its properties and methods), `function` (public and `internal/`), and top-level `type` alias or `const` in `src/**` and `test/fixtures/**` must carry a complete `/** ... */` JSDoc block per `docs/CODING_GUIDELINES.md` §2 (clear summary sentence, behavioral description when non-obvious, and complete `@template`, `@param {Type} name - Description`, `@returns {Type} Description`, and `@throws` / `@note` / `@example` tags where applicable, with zero inline or body comments), enforced by `pnpm --filter @paraharness/core lint`.

### 4.1 `ScopeLockManager` & Serialized Per-Step `StepContinuationQueue` (`SPEC.md` §3.7.2 & `CODING_GUIDELINES.md` Rule 3.5)
1. **Approved Library Usage (`p-queue`, `p-limit`, `diff`, `@dagrejs/graphlib`)**:
   - Use `p-queue` (`concurrency: 1`) inside `StepContinuationQueue` and `ScopeLockManager` writer serialization, `p-limit` for bounded fork/speculate concurrency, `diff` (`createTwoFilesPatch`) inside `computeInRunGroundingDiffs`, and `@dagrejs/graphlib` (`Graph`, `alg.findCycles`) for dynamic prerequisite cycle detection in `executeAddDependencies` / `LaneScheduler`.
2. **Per-Handle Shared-Read / Exclusive-Write Lock (`ScopeLockManager`)**:
   - `acquireRead(handle)` grants concurrent shared read leases around `scope.forkChild`, `scope.inspect`, and parent tools with `effectTracking: 'declared'` whose `describeEffects` return only non-mutating effects (`mutatesScope !== true`).
   - `acquireWrite(handle)` grants an exclusive write lease around `scope.commitChild`, `scope.syncChild`, `scope.syncRoot`, and parent tools whose `describeEffects` include `mutatesScope: true` or whose `effectTracking === 'subprocess-post-flight'`. Child forks execute against their own isolated `childHandle` without holding locks on `parentHandle`.
2. **Per-`stepExecId` Serialized Continuation Queue (`StepContinuationQueue`)**:
   - Serializes all calls to `LedgerStore.updateContinuationStack(runId, stepExecId, continuationStack, opts)` through an in-memory per-`stepExecId` async FIFO queue so concurrent child forks in `'fork-batch-frame'` and speculative branches in `'speculate-frame'` never overwrite sibling state transitions.

### 4.2 Run-Immutable `CompiledWirePrefix`, Role-Scoped vs Union Tools & `[ROLE_AND_SCOPE_CONTEXT]` (`SPEC.md` §3.2.1)
1. At flow run start, compiles each `PrefixGroupNode` in strict AST declaration order (`.sharedGrounding(...)` -> `.sharedInstructions(...)` -> `.sharedRules(...)` global rules via `ctx.registry.sources`), snapshots `groundingSnapshots` (`{ sourceId, text, digest }`), compiles `wireToolSchemasByRoleKey` using `zodToJsonSchema` (`keyed by roleKey` in `'role-scoped'` mode, including `.withTools()` derived keys `"${baseActor.id}+tools:${sortedExtraToolNames.join(',')}"`, or `'*'` with `[Role: <actorId>]` descriptions in `'union'` mode), and pins `compiledPrefixesJson` in `LedgerStore.createOrResumeRun`.
2. Never mutates byte 0 of `systemPromptText` mid-run; when grounding files or `TopologyStore` contracts change mid-run, computes `updatedGroundingDiffs` (by invoking `ctx.registry.sources` with `{ ...ctx, scopeHandle }`) and live partition contracts/epochs (`TopologyStore.getPartitions(runId)`) and injects them into Turn-0 `[ROLE_AND_SCOPE_CONTEXT]` and `[TOPOLOGY_SYNC]` / `[PREREQUISITE_SYNC]` frames.

### 4.3 Two-Phase Guard Evaluation, Post-Flight Subprocess Sandboxing, `PendingToolBatch` Replay & `.onLimitExceeded()` (`SPEC.md` §3.5)
1. **Chained Guard Clause Order**: Evaluates all `'deny-with-error'` clauses in declaration order before any `'raise-interrupt'` clause. Each guard filters `violatedEffects` down to only the violating resources not covered by `activeLeases` (`agent-frame.activeLeases` $\cup$ `loop-frame.grantedLoopLeases`).
2. **Pre-Flight Batching**: When call $i$ (`effectTracking: 'declared'`) passes all `'deny-with-error'` clauses and fails a `'raise-interrupt'` clause $C$, inspects `(i..k)` via `describeEffects` and batches into `blockedCalls` (tagging with `blockedPreFlight: true` and `adjudicatedClauseIds: [...(call.adjudicatedClauseIds ?? []), C.id]`) only those calls in `(i..k)` that pass all `'deny-with-error'` clauses and fail the exact same clause $C$, persisting all unfinished calls `(i..k)` in declaration order in `PendingToolBatch.remainingCalls`.
3. **Post-Flight Subprocess Sandboxing (`effectTracking: 'subprocess-post-flight'`)**:
   - Before invoking call $i$, snapshots `preToolCkpt = await scope.serializeCheckpoint(scopeHandle)` and persists `pauseState.inFlightPreToolCheckpoint = preToolCkpt` in `LedgerStore`.
   - Wraps `toolDriver.execute(toolNode, args, ctx)` in `try/catch`: on throw or `AbortSignal`, unconditionally calls `await scope.restoreCheckpoint(scopeHandle, preToolCkpt)` before clearing `inFlightPreToolCheckpoint`.
   - After normal completion, computes `synthesizedEffects = await scope.diffEffects(preToolCkpt, scopeHandle)` and evaluates policy guards (`'deny-with-error'` then `'raise-interrupt'`) before `ctx.recordEffects(synthesizedEffects)`: if disallowed, calls `await scope.restoreCheckpoint(scopeHandle, preToolCkpt)`, records the rollback error in `completedResults` (setting `activeInterruptCallId = call_i.id` on `'raise-interrupt'`), clears `inFlightPreToolCheckpoint = undefined`, and never re-executes the rolled-back subprocess call on `.resumeWith()`.
4. **Declaration-Ordered `remainingCalls` Drain on `.resumeWith(feedback)` & Nested `.adjudicateWith()`**:
   - When `.onInterrupt()` is nested inside `.adjudicateWith()`, `$esc.elevateLeaseWhen()` attaches the granted `LeaseDelta` to the **outer interrupted actor's** `agent-frame.activeLeases` and enclosing `loop-frame.grantedLoopLeases`, while `$esc.resumeWith()` resumes `pauseState.pendingAdjudication.adjudicatorStack`.
   - When the outer `.resumeWith(feedback)` runs, persists `adjudicationFeedback: feedback`, resolves `activeInterruptCallId`, and drains `remainingCalls` strictly in `(i..k)` declaration order through the full per-call pipeline (prepending `[Lease Elevated: ${feedback}]\n\n` on `blockedPreFlight: true` calls, or recording `[Lease Denied: ${feedback}]` and skipping dependent trailing calls with `[Skipped: Preceding tool call in turn batch was denied]`).
5. **4-Step Crash-Safe `.onLimitExceeded()` Sequence**:
   - Step 1: Synthesizes `{ callId, content: '[Aborted: Limit Exceeded]', isError: true }` for any unexecuted calls in `remainingCalls` and writes the complete `role: 'tool'` wire frame to `LedgerStore`.
   - Step 2: Sets `pausedAtPhase = 'LIMIT_EXCEEDED_FLUSH'` and `pauseState = { kind: 'interrupt-flush', interruptId, flushPromptInjected: true }`, appends `[LIMIT_EXCEEDED_FLUSH]` via `ModelDriver.appendToolResultNotes`, invokes 1 final turn with `toolChoice: 'none'`, `effort: 'low'`, and `outputSchema: interrupt.schema`, and persists `flushedInterruptPayloadJson`.
   - Step 3: Stops all active `'scope'`, `'fork'`, and `'skill'` `ServiceSession` daemons, executes `abortHook` (or `restoreCheckpoint`), calls `TopologyStore.resetRunOverlay(runId, { scope: 'step', stepExecId })`, and persists `abortMetaJson`.
   - Step 4: Atomically persists `recordStepTransition({ stepExecId, status: 'INTERRUPTED', telemetryJson })` (discarding `accumulatedLessonOutcomes` and `bufferedGateRecoveries`), `updateRunInput(runId, { inputJson: replacementInput })`, and `recordStepStart` for `replacementExecutable` (`executableId: replacementExecutable.id`).

### 4.4 Downward `.fork()`, Speculative `.speculate()`, `.mutatePlan()`, `.onChildInterrupt()` & `resumeFork` (`SPEC.md` §3.7.2)
1. **Downward `.fork()`**: Supports `'shared-prefix-only'` and `'clone-transcript'`, attaches `scope.getConflictLease?.(childHandle)` on `forkChild` and conflicted `commitChild`, persists `status: 'CHILD_COMMITTED'` before calling `LessonStore.recordOutcomes()`, and bounces conflicts up to 2 retries by rolling enclosing `loop-frame` back to `phase: 'act'` at `preservedActLeafMessageId` and appending `[COMMIT_CONFLICT]`.
2. **Speculative `.speculate()`**: Parks branches hitting exogenous `P.human` escalations or unhandled upward interrupts as `PARKED_ON_ESCALATION`; enforces Post-Race Cases 1–4 (never short-circuiting when $\ge 1$ branch is parked, $\ge 2$ branches are parked, or `humanRulingsHistory.length > 0`); enforces built-in `beforeStop` candidate index validation on `arbiterAgent`; keeps losing candidate worktrees alive during `refineWinnerWhen` and conflict-bouncing `commitChild`; persists `WINNER_COMMITTED` before flushing `bufferedLessonOutcomes`; and on `'unpark-escalation'`, retains all `COMPLETED` sibling handles alive and persists `humanRequestId` before calling `HumanAdapter.requestDecision` (or returns `ABORTED_ON_CHILD_INTERRUPT` for upward interrupts).
3. **Dynamic `.mutatePlan()`**: Chains spawned prerequisites linearly ($T_{\text{prevTip}} \leftarrow T_1 \leftarrow \dots \leftarrow T_k \leftarrow T_{\text{parent}}$), runs initial `syncRoot` on `QUEUED -> RUNNING`, suspends parent with `headScopeCheckpoint` and `inherit-parent-with-boost`, and on wakeup restores `headScopeCheckpoint` before `syncRoot` (replay-idempotent), persists `syncedToPrerequisiteCheckpoint` before re-acquiring services and draining `remainingCalls`, and handles `[PREREQUISITE_FAILED]`.
4. **Upward `.onChildInterrupt()` & `resumeFork`**: Evaluates turn-batch barrier across siblings (cancelling pending sibling human decisions via `HumanAdapter.cancelDecision`, classifying `TOOL_BOUNDARY` Case B vs `BEFORE_STOP_GATE` Case C, rolling evaluator-raised interrupts back to `preservedActLeafMessageId`, and snapshotting `childScopeCheckpoint`); supports multi-ID `resumeFork` wire aggregation, `action: 'abort'`, replay-idempotent `restoreCheckpoint(childScopeCheckpoint)` + `syncChild` + `syncedToParentCheckpoint`, Cases A/B/C (with `neutralSyncContinuation: true` in Case C), and atomic `resolveSuspendedFork("${forkId}#${epoch}", 'RESUMED')`.
5. **Mixed-Turn Tool Batching (`SPEC.md` §3.7.2)**: When a single model turn emits regular tools `(1..m)`, capability tools `.fork()`/`.speculate()`/`spawnTasks` `(m+1..p)`, and trailing regular tools `(p+1..k)`, executes `(1..m)` first (persisting results in `completedResults`), dispatches `(m+1..p)` (recording outputs in `completedResults`), and drains `(p+1..k)` in declaration order so all `(1..k)` tool results are written into a single `role: 'tool'` wire frame.

### 4.5 `P.rules` & `P.scopedRule`, `P.loop` Isolation, `P.lane.tracker`, and `P.stream` / `P.harness` (`SPEC.md` §3.1, §3.4.1, §3.8, §3.10)
1. **`P.rules` & `P.scopedRule` (`SPEC.md` §3.4.1)**:
   - Evaluates `when.partitions` against `ctx.activePartitions` at Turn 0 and injects matching rules into `[ROLE_AND_SCOPE_CONTEXT]`, recording their IDs in `injectedScopedRuleIds`.
   - Evaluates `when.effects` reactively against each tool call's `ToolEffect[]`; when a rule not yet in `injectedScopedRuleIds` matches `call_i`, appends its directive to `call_i`'s result in `completedResults` and records `rule.id` in `injectedScopedRuleIds` (preserving the injected directive in `completedResults` even if a subsequent `call_2` in the same batch suspends the step).
   - In `evaluateBeforeStopGate`, runs `rule.enforceBeforeStopChecks` if and only if `rule.id` is in `injectedScopedRuleIds` **and** `observedEffects` contains at least one effect with `mutatesScope === true`.
2. **`P.loop` Step-Boundary Isolation & `.act()`-Only Quantitative Tripwires (`SPEC.md` §3.8)**:
   - Quiesces all `'skill'`-scoped `ServiceSession` daemons on every `.act()` $\to$ `.evaluate()` step boundary (`quiesceScopeServices`).
   - Isolates evaluator `activeSkillIds` ephemerally inside the evaluator's `agent-frame` without polluting `loop-frame.activeSkillIds` or `loop-frame.activeSkillActivations`.
   - Increments quantitative tripwire counters (`actTurnsTaken`, `actCostUsd`, `actElapsedDurationMs`) strictly during `.act()` turns while tracking cumulative telemetry across both `.act()` and `.evaluate()`.
3. **`P.lane.tracker` & Canonical `stateMappings` (`SPEC.md` §2.8 & §3.10)**:
   - `LaneTrackerConfigBuilder` populates `LaneNode.tracker.stateMappings` with canonical keys `'queued'` (`.onQueued`), `'running'` (`.onRunning`), `'waiting'` (`.onWaiting`), `'errored'` (`.onErrored`), `'cancelled'` (`.onCancelled`), and `'exit:${exitState}'` (with fallback `exitState` for `.onExit(exitState, externalState)`).
   - `LaneScheduler` polls `TrackerAdapter.poll()`, filters and maps items via `fromIssue(raw)` (skipping `undefined`), and looks up the exact canonical keys (`'queued'`, `'running'`, `'waiting'`, `'errored'`, `'cancelled'`, and `` `exit:${exitState}` `` with fallback `exitState`) in `lane.tracker.stateMappings` when invoking `trackerAdapter.setExternalState(itemKey, mappedState)`.
4. **`P.stream` & `P.harness` Lifecycle (`SPEC.md` §3.1 & §3.10)**:
   - Subscribes to each declared `StreamSource.subscribe(onEvent)` on `runtime.start()`, evaluates `filterFn(raw)` synchronously, maps matching events via `mapPayload(raw)`, and routes emitted signals through `controller.emitSignal(streamNode.signal.id, payload)`.
   - Executes `.onSignal(signal).notify(human, mapper)` by invoking `humanAdapter.notify(mapper(payload))`, and manages all `.expose(controlPlane)` adapters by storing the `{ close(): Promise<void> }` handle returned by `await controlPlane.start(controller)` on `runtime.start()` and invoking `await handle.close()` on `runtime.stop()`.
