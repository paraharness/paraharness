# Lessons (General)

- **[Dependency Selection & Version Pinning]** Query live registry metadata (`npm view <pkg> version license deprecated`), GitHub maintenance/open-issue status, OSV advisories, and native capabilities in the latest stable major of existing dependencies (such as `zod` v4 `z.toJSONSchema()`) before proposing or pinning any package, because relying on training-cutoff memory installs outdated majors (`zod` v3), proposes archived or redundant companion packages (`zod-to-json-schema`), or recommends incomplete single-package replacements (`yaml` without frontmatter fence extraction).
- **[Cross-Package Utilities & Standalone Workspace Packages]** Extract any Owner-approved custom infrastructure utility (such as cross-process file locking in `@harness-dsl/lockfile`) into its own standalone `packages/<name>` workspace package rather than baking it inside one adapter or copy-pasting helper files across packages, because duplicating helpers across packages multiplies bug surfaces and drifts implementations across waves.
