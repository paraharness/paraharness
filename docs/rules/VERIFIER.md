# Verifier Rules

1. **Verify Every Finding in a Strictly Read-Only Repository Pass Against Actual Code, Architecture, and Spec**
   Inspect `git diff origin/main...HEAD` / `git diff <pre_remediation_sha>..HEAD` and read the implicated target, source, test, `docs/SPEC.md`, and `docs/CODING_GUIDELINES.md` lines to trace the actual execution path and module structure before admitting or rejecting a finding, making zero repository file edits or state-mutating git commands (never running `git commit` or `git push`; isolated `$TMPDIR` scratch verification outside the repository is permitted when required by the active loop).

2. **Admit Genuine Architecture, Single-Responsibility (`Rule 3.1`), Bug, and Smell Findings (Never Use `pnpm lint` as a Shield)**
   Evaluate each candidate against the active loop's Admission and Rejection Gates independently of the Reviewer's proposed fix:
   - **Admit** any finding that satisfies the active loop's Admission/Defect Gate—including a behavioral, concurrency, lifecycle, wire/SQL/git, or type defect, a function or method that mixes multiple responsibilities or levels of abstraction (`Rule 3.1`), nested control flow (`Rule 3.2`), a module taxonomy or JSDoc violation (`§§1–2`), a hand-rolled commodity utility where an Owner-approved library is mandated (`Rule 3.5`), or a weak/smelly test (`§6`). Never reject a genuine single-responsibility, abstraction-level, readability, or decomposition defect on the excuse that `pnpm lint` passed or that `plan_file` §3 listed a coarse module table.
   - **Reject** only candidates that match the active loop's Rejection Gate—whose underlying claim is factually false against the actual code/spec, contradicts a prior settled ruling in `<round_history>` when the target lines are unchanged, demands an unrequested feature outside the active loop's scope, or flags already-clean decomposition of a workflow into focused single-responsibility `internal/` helpers.

3. **Provide Concrete Proof and Clean Surgical Fix Options**
   If a candidate proves a real defect under the Defect Gate even when the Reviewer's proposed fix is flawed, admit the underlying defect and output the exact `file:line` quote, the concrete proof of the bug or design/guideline violation, two compliant surgical fix options (`Option A`, `Option B`) with trade-offs when genuine design or decomposition choices exist (or a single direct surgical `Option A` when the spec or guideline leaves only one clean form), and your recommended pick.
