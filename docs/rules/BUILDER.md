# Builder Rules

1. **Write Clean, Single-Responsibility Code at One Level of Abstraction & Enforce the Library-First Mandate (`Rules 3.1–3.5`)**
   Write clean, maintainable code where every file, class, method, and function has **one clear responsibility at a single level of abstraction** per `docs/CODING_GUIDELINES.md` §§1–3. Decompose orchestrators, pipelines, and stateful classes inside `owned_dirs` into focused `internal/` phase, predicate, and projection functions whenever responsibilities separate—never treating `plan_file` §3 as a cap on extracting helper modules, never cramming multiple phases into one function, and never compressing multiple statements onto long lines. Use the exact Owner-approved libraries mandated by `docs/CODING_GUIDELINES.md` Rule 3.5 and `plan_file` §1 rather than hand-rolling commodity utilities.

2. **Apply Document Precedence & Escalate Only True Upstream, Spec, or Dependency Blockers**
   Follow the precedence hierarchy in `docs/rules/GENERAL.md` Rule 2 (`CLAUDE.MD` > `docs/SPEC.md` & `docs/CODING_SAMPLE.md` > `docs/CODING_GUIDELINES.md` > `plan_file`), and pause mid-turn via `send_message` **only** for `BLOCKED_ON_UPSTREAM` (requires editing `forbidden_dirs` not yet authorized in `upstream_patches`), `SPEC_CONTRADICTION` (direct contradiction between governing documents or between `$verified_findings` / `$verified_changes` and a higher-ranked governing document or spec-mandated test), `PROPOSAL_INFEASIBLE` (an Owner-approved signature or AST contract cannot be built without altering the approved contract), or `UNAPPROVED_DEPENDENCY` (a non-domain concern requires an external library or custom standalone `packages/<name>` package not yet approved in `docs/CODING_GUIDELINES.md` Rule 3.5 / `plan_file` §1, or a planned dependency fails live `npm view`/GitHub/OSV checks or contract coverage).

3. **Apply In-Scope Cascades Autonomously & Report Unrelated Adjacent Defects at Completion**
   Apply direct in-scope cascade updates inside your assigned target scope (`owned_dirs` and Head-authorized `upstream_patches` in `IMPL_LOOP`, or the active loop's target files) required by `$verified_findings`, `$verified_changes`, or `$approved_proposals` autonomously without asking, and record any unrelated adjacent defects discovered in a `disclosed_adjacent_defects` section of your completion report (without halting mid-turn) for the next round's Review and Verification Gate.

4. **Fail First, Fix Second**
   When modifying code in `src/**`, reproduce every behavioral/runtime bug or approved shorthand/default contract with a failing test before modifying `src/**`, and never weaken or tailor a test assertion to match buggy code, because a fix whose test never failed proves nothing.

5. **Trace Every Diff Line to the Task**
   Touch only files inside your assigned target scope (`owned_dirs` and Head-authorized `upstream_patches` in `IMPL_LOOP`, or the active loop's target files) required by the milestone or `$verified_findings`, `$verified_changes`, or `$approved_proposals`, delete only what your change leaves unused, and never leave stubbed no-ops, hardcoded test-input branches, or silent fallbacks.

6. **Exit Only on a Green Scoped Verification Gate & Commit Locally (Never Push)**
   Run the active loop or unit's `gate_cmd` and verify zero new or newly modified files in `<non_sibling_forbidden_dirs_excluding_upstream_patches>` (in `IMPL_LOOP`) or outside your assigned target scope (in `ERGONOMICS_LOOP`, `HARNESS_LOOP`, `SPEC_LOOP`, and `PLAN_LOOP`) relative to `baseline_dirty` before returning; make frequent scoped local commits at logical sub-milestones and at step completion once green via `lockf -k -t 30 .git/harness-commit.lock sh -c "git add -- <target_scope> && git commit -m '<scope>: <summary>' -- <target_scope>"` (serializing `.git/index` access across parallel Builders), include the commit SHA and `git status --porcelain` / `git diff --stat origin/main...HEAD -- <target_scope>` in your report, **never** run `git push`, and never run `git checkout`, `git restore`, `git clean`, or `git reset` outside your assigned target scope.
