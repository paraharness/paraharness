# Reviewer Rules

1. **Complete the Audit in One Strictly Read-Only Autonomous Pass (`NO_FINDINGS` When Clean, With a Compact Falsifiable Trace)**
   Audit your assigned target scope (`owned_dirs` and `upstream_patches` in `IMPL_LOOP`, or the target spec, plan, or harness files) against your assigned lens with zero file edits or state-mutating commands (never running `git commit` or `git push`): in Round 1 (`round == 1`), inspect `git diff --stat origin/main...HEAD -- <target_scope>` (plus full `git diff origin/main...HEAD` only for pre-existing modified files such as `package.json`, `<upstream_patches>`, `SPEC_LOOP`, or `HARNESS_LOOP`) and read the lens-scoped files in `<target_scope>` in full once; in Round $r \ge 2$ (`round > 1`, after `Step 3` remediation), inspect `git diff <pre_remediation_sha>..HEAD -- <target_scope>` (all commits since `Step 3` began) and `git diff --stat origin/main...HEAD -- <target_scope>`, reading in full only the files touched by the remediation commits and their direct callers/dependents. Return every candidate defect in a single report (`NO_FINDINGS` when clean), plus a **5–8 line falsifiable audit trace** naming the 3–5 most complex orchestrators/functions/classes you inspected with their exact `file:line` range, what single responsibility each performs, and which phase helpers/invariants it delegates to (never generic prose checklists like "checked Rule 3.1 — OK").

2. **Never Treat `pnpm lint` or `vitest` Passing as Proof of Code Quality (`CODING_GUIDELINES.md` > `plan_file`)**
   Mechanical gates (`pnpm lint`, `tsc`, `vitest`) only check syntax and basic rules; they cannot judge whether a function is well-designed. `docs/CODING_GUIDELINES.md` strictly outranks `plan_file` per `docs/rules/GENERAL.md` Rule 2: any violation of `docs/CODING_GUIDELINES.md`—including functions or methods that mix multiple responsibilities or levels of abstraction per **Rule 3.1** (such as mixing high-level phase orchestration with inline context casting, state-object assembly, scoring math, raw I/O, or error recovery), nested control flow instead of guard clauses per **Rule 3.2**, disallowed entity co-location per **Rule 1.1**, unreachable interfaces per **Rule 1.2**, grab-bag naming per **Rule 1.8**, or missing/stubbed JSDoc per **Rules 2.1–2.3**—is a mandatory Defect Gate `(e)` finding even if `pnpm lint` passed and even if `plan_file` §3 grouped those responsibilities together. Include the exact `file:line`, quoted snippet, violated requirement, and concrete explanation for every finding.

3. **Review With Genuine Engineering Judgment Across Architecture, Logic, Cleanliness, and Tests**
   Review every file as a senior engineer responsible for maintaining the codebase: hunt broken state transitions, concurrency/lock races, resource/listener leaks, wire/SQL/git mismatches, mixed-responsibility functions and tangled control flow (`Rules 3.1–3.2`), $O(N^2)$ hot-path allocations (`§4`), hand-rolled commodity utilities where an Owner-approved library is mandated (`Rule 3.5`), code smells, and weak or tautological tests (`§6`).
