# Reviewer Rules

1. **Complete the Audit in One Strictly Read-Only Autonomous Pass (`NO_FINDINGS` When Clean)**
   Audit your assigned target scope (`owned_dirs` and `upstream_patches` in `IMPL_LOOP`, or the target spec, plan, or harness files) against your assigned lens with zero file edits or state-mutating commands (never running `git commit` or `git push`): in Round 1 (`round == 1`), inspect `git diff --stat origin/main...HEAD -- <target_scope>` (plus full `git diff origin/main...HEAD` only for pre-existing modified files such as `package.json`, `<upstream_patches>`, `SPEC_LOOP`, or `HARNESS_LOOP`) and read the lens-scoped files in `<target_scope>` in full once; in Round $r \ge 2$ (`round > 1`, after `Step 3` remediation), inspect `git diff <pre_remediation_sha>..HEAD -- <target_scope>` (all commits since `Step 3` began) and `git diff --stat origin/main...HEAD -- <target_scope>`, reading in full only the files touched by the remediation commits and their direct callers/dependents, and return every candidate defect in a single report (`NO_FINDINGS` when clean).

2. **Cite Exact Locations, Enforce Document Precedence (`CODING_GUIDELINES.md` > `plan_file`) & Report Structural/JSDoc Violations**
   Include the exact `file:line`, quoted snippet, violated requirement (`docs/SPEC.md`, `docs/CODING_GUIDELINES.md` rule number, or `plan_file`), and failure trace for every finding; `docs/CODING_GUIDELINES.md` strictly outranks `plan_file` (`CLAUDE.MD` > `docs/SPEC.md` & `docs/CODING_SAMPLE.md` > `docs/CODING_GUIDELINES.md` > `plan_file`), so any `docs/CODING_GUIDELINES.md` violation (co-located entity kinds, `> 1` top-level interface in a file, or missing 3-part JSDoc on an interface method, class method, function, interface, or class) is a mandatory Defect Gate `(e)` finding where the `rule + file:line` citation is the complete proof, even if `plan_file` grouped those symbols together.

3. **Hunt Both Semantic/Concurrency/Performance Defects, Hand-Rolled Commodity Re-Implementations (`Rule 3.5`), and Objective `CODING_GUIDELINES.md` Violations**
   Hunt broken state transitions, lock/lease races, resource/listener leaks, wire mismatches, $O(N^2)$ hot-path allocations, hand-rolled commodity utilities where an Owner-approved library is mandated by `docs/CODING_GUIDELINES.md` Rule 3.5, weak or tautological tests, and objective `docs/CODING_GUIDELINES.md` taxonomy/JSDoc violations (§§1–6); refrain only from subjective prose rewording when `docs/CODING_GUIDELINES.md` is already fully satisfied.
