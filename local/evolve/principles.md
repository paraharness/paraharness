# harness-dsl design principles

These are the owner's decisions. A variant that violates one is worse, however elegant. A variant may propose changing one only by stating the principle it breaks and why, in its design notes.

## Vision

1. **Stateless LLMs, stateful harness.** Every model call is a pure function. All state lives in the harness. The harness gets better over time not because models learn but because it feeds the right memory to the right call.
2. **The harness is about work.** Units of work, kinds of work (Bug, Feature, Epic, ServiceHeartbeat, Exercise), hierarchies of kinds, lifecycles, where work comes from, where its state lives, what runs next. The framework is honest about this. It does not hide behind "general purpose".
3. **An LLM is a component, not a requirement.** A harness with zero model calls is a first-class harness. Deterministic scripts and model calls compose through the same executable interface. A step is a command, a model call, a batch of model calls, or an external job (submitted now, collected later by a poll or a callback: a cloud batch, a GPU run, a long service call); a batch and an external job hold no capacity while they run. (External jobs ruled 2026-11-01 after run one.)
4. **Intelligence lives in determinism.** Policies (what to pick, what to recall, what to schedule) are deterministic functions, authored once, reading harness state and metrics at decision time. Policies never change themselves. The harness changes behaviour because policies read changed state.

## Dividing line

5. **Opinionated about shape, agnostic about backend.** The kernel defines what a work unit, a lifecycle, a memory item, a policy, a ledger entry *is*. It never cares where any of them is stored, which vendor serves a model, or which tool the operator uses. Like Eloquent: strict about how you model, indifferent to which database.
6. **Defaults ship, and pass the delete test.** First-party backends ship in the box (SQLite ledger, JSONL memory store, Claude Code driver, folder supplier). Each is one implementation of a public interface. Delete any of them and the kernel still compiles and runs.
7. **`H.*` is kernel vocabulary only.** Shapes and builders. Anything with a backend lives in a subpath (`harness-dsl/claude-code`, `harness-dsl/sqlite`, `harness-dsl/linear`), whether first-party or not. No vendor, CLI, file format or product name appears in `H.*`.
8. **Three sorts of entity.** *Kinds* are pure vocabulary and carry no backend (work kind, state, memory kind, role, resource, halt). A resource (a file pattern, a database, a section, a host) is a named shared thing that leases, memory scope and metric facets reference by identity; a string never stands in for it. A halt is a named question with a decision schema that grants, metrics, timers and policies reference by identity. *Instances* are specific resources and carry their backend (account, model, runner). *Pivots* connect kinds and instances per harness (pool = accounts × policy, agent = role × model, lane = work kind × suppliers × store × handler, journal = memory kind × store × recall, seat = role × models × choice policy: a seat holds a role with the model a deterministic policy picks at attempt time, an agent is a seat with one model, and metrics on an A/B comparison key on the seat so a model swap does not break the series). (Resources, halts and seats ruled 2026-11-01 after run one.)
9. **Every pivot has a noun.** A pivot enters the DSL only when we can name what it produces. `bind`, `wire`, `attach`, `connect` are not nouns; they are the absence of a concept.
10. **Relationships do not live on kinds.** A work kind does not know who supplies it, stores it or handles it. A role does not know which model runs it. Putting a relationship on a kind makes the kind less reusable.

## Mechanics

11. **Descriptors are immutable and stateless.** Every builder method returns a new descriptor. Nothing is read from the environment at definition time; `H.env('NAME')` and `H.slot.port(n)` are references the runtime resolves. Derived descriptors must be renamed; the runtime refuses two descriptors with one name.
12. **Lifecycle skeleton.** An attempt has one of three outcomes: succeeded, failed, cancelled. This is the harness's track record, and metrics on models, agents, runners and accounts are computed from it. A unit is at one of four positions: pending, active, waiting (parked, holding no capacity, not schedulable), terminal. The scheduler and the board are defined on positions. A kind's named states are entities (shareable); each declares its position, and each terminal state declares its verdict for the kind's own outcome rate: success, failure or neutral, with no default. Blocked (waiting on a human) is an attempt state, not a unit state. A unit outlives its attempts. By default a failed attempt leaves the unit at pending under the lane's retry policy, and the lane's policy names where exhaustion leaves the unit, in the kind's own states; the kind declares nothing about failure. Where an active unit stands in its work is its attempt's current step, read from the ledger; a kind declares no states for it, and waiting on a human is the attempt's blocked state, recorded once. (Amended 2026-11-01 after generation 0: eight of eight variants broke the five-outcome form, and the adversaries showed why. The failure default was added after generation 1, when three of eleven children read the silence as "every kind declares a failure state" and invented states that loop or dead-end. Retry's end state moved to the lane, and the active position was ruled, on 2026-11-01 after run one: three generation-3 adversaries showed a move on the kind only means something given the lane's policy, and three generations modelled waiting on a human twice.)
13. **Triggers are relationships.** A trigger connects a source (a transition, later also time, external events, metric thresholds) to a consequence (create work in a lane, run an executable, record memory). Flows stay blind to other kinds. Triggers fire only from recorded ledger events and their firings are recorded.
14. **Memory is forward-phrased and atomic.** "Do X when Y because Z", never history. The kernel owns the envelope (id, created, `when`: the kinds, roles, skills and resources an item applies to). Recall is a deterministic policy over items and scope, ranked by specificity and by track record (items present in succeeded attempts rise). Experience (can be wrong, stale, deduped) and taste (the owner's preference, never wrong, broadly scoped) are different kinds.
15. **The ledger is the kernel's only state.** Runs, attempts, invocations, transitions, the pending queue, quota. Its backend is pluggable, and it may be partitioned by backend. Account quota shared by several harnesses is a ledger partition of append-only quota events: each harness appends its own consumption and folds the window at read time, so no harness takes a lock over another's account state. The account names its quota partition, as every instance carries its backend; the ledger carries no option for it. A quota store that needs the ledger's single-writer lock, or a second store under the ledger's name, breaks this principle. There is no kernel work store: domain state lives where the owner's adapter puts it, and a unit may have no store at all. (Shared quota ruled 2026-11-01 after generation 1.)
16. **Supply, store and scheduling are three pillars.** Suppliers produce units (folder, poll, webhook, schedule, operator). Stores hold unit state (one adapter may be both). The scheduler decides what runs next from pending units, lane WIP limits, capacity (runner slots, account eligibility) and a policy. Without a scheduler there is a library, not a harness.
17. **Human-in-the-loop is kernel.** Halting an attempt for an outside decision is universal. Who resolves it, through which surface, is not: the supervisor is one optional client of a control API made of operations, and operations (not capability strings) are what a client is granted; a grant names the halt it may resolve. A halt's resolver is a human, a registered policy (a deterministic function whose decision is recorded with the metrics and sample counts it read), or a clock: a timeout default that resolves the halt without cancelling the attempt. Deadlines on a halt run from the recorded halt, never from unit data. (Ruled 2026-11-01 after run one.)
18. **Metrics are queryable and honest.** Computed from ledger transitions, with sample counts beside every rate, so policy authors write exploration deliberately. Success is defined by the kind's terminal states, never by "the flow finished". A metric dimension is a typed ledger column (kind, lane, state, model, seat, resource, halt) or a declared facet entity; a facet that repeats a column is a startup error. (Ruled 2026-11-01 after run one.)

## Ergonomics standards

19. A first-time reader predicts what each line does from its name. Builders chain. Names are nouns for things and verbs for settings. Units sit in names or types (`budgetTokens`, `maxUsd`), never implied.
20. Full inference. Scenario code needs no `as`, `any`, `!` or `@ts-ignore`. A `.d.ts` that uses `any` to make inference "work" fails this standard.
21. Small surface. The fewest entities and methods that express the whole scenario battery without escape hatches. An entity with one use is suspect. A method nobody in the battery calls is removed.
22. No two words for one thing. Run, attempt, invocation, step have one definition each, or fewer words.
